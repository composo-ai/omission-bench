# Figure and table sources

**What is in this directory.** The data behind every figure and table in the two papers:
one JSON file per float, and a markdown twin of each table. `extract_data.py` is here too,
because five analysis modules in this repository load it for the study's measure
conventions.

**What is not.** The rest of the figure and table code - the other extract-and-check
scripts and the renderers, both named below - lives with the paper source and is not part
of this release. There are two reasons. Every extract-and-check script reads
run stores and construction corpora that this release does not carry, so none of them could
run for anyone outside the study; `extract_data.py` ships in spite of that, for the
conventions other modules take from it, and its own `main()` cannot be run here either. And
the renderers need a plotting library that is not in this repository's pinned requirements,
because the figures were drawn in a different environment from the harness. What a reader
can check is the other direction: each data file below records which artifacts its numbers
came from, and the papers print the same numbers.

All numbers recomputed from the record stores, never hand-typed. F1/F3/F4/T6/T7 are built by `extract_data.py` -> `_recomputed.json` -> `build_figure_data.py`; the 2026-08-17 floats each carry their own extract-and-check script (`extract_t1_t2.py`, `extract_t3_f2.py`, `extract_t4_t5.py`, `extract_t8.py`, `build_f5_data.py`), every one of which cross-checks its recomputed values against the figures the papers report and refuses to write on a mismatch. Rendering: `render_f1.py`, `render_f2.py`, `render_f3.py`, `render_f4.py`, `render_f5.py`, `render_tables.py` (T8 and T1-T5 render inside their extract scripts); shared style `vizstyle.py` (dataviz-skill palette, colourblind-safe).

2026-08-24 (figures rebuild for the two-routes reframe): `extract_data.py`'s threshold sweep is inclusive-aware (the strict-`<` sweep could not express a cut that includes records sitting exactly on an interior threshold - the checklist arm's swept cell now reads 16.0% from the store, matching the published value without the hand-correction both papers' T6s carried; the only other cell that moved is the ragas-faithfulness component's swept detection, 11.4% -> 11.6%, quoted nowhere). The same script restricts the confirmation blocks to the 151-pair held-out subset (confirm-B3.jsonl carries the full 495-pair evaluation set since the 2026-08-24 evaluation-set extension) and adds a `pipeline_evalset` block checked against the published evaluation-set operating points. Evaluation-set figures for the route rows come from `results/w2-evalfull/analysis.json` (`w2_evalfull_analyze.py`, extended with per-replicate paired blocks, per-residual detection, the Gemini majority collapse and receipts costs).

2026-08-25 (judge-paper revision: terminology, T1 redesign, T7 split, one new figure). **No measured value changed anywhere** - every builder still cross-checks against the figures the papers report and still refuses to write on a mismatch, and a token-by-token numeric diff of every regenerated `.tex` and `.json` against the 24 Aug outputs comes back empty apart from the version tag dropped from the judge's name. The released dataset's own field values are untouched: `partial-weak` and `partial-strong` remain the data keys, and T3's vocabulary block still names them. Touched: `extract_t3_f2.py` (T3 panel (b) rows, the omissions gloss, the unpopulated-cell footnote, F2's graded-twins stage), `build_f5_data.py` (F5's level labels, series labels and the whole caption), `render_f5.py` (axis ticks, the detection annotation, the reference-judge band note), `render_f1.py` + `build_figure_data.py` (F1's third column, "Restatement-trace twin", and its footer).
